## Two targets

Every score in this document answers one of two questions, and they no longer
give the same answer.

**Against the pin** is what the oracles measure. `b78b451` is the commit every
committed corpus was captured from, so a replay is only an oracle for that
revision. This is the number that moves when work lands here.

**Against upstream `HEAD`** is what a user comparing the two products
experiences. The pin is v2.24.0 and upstream is v2.24.2, which is 201 source
files and roughly +13 900 / -3 700 lines apart, measured with `git diff --stat
b78b451..HEAD -- vibe/` in the reference checkout. Some of that drift is
renaming this port's whole session surface out from under it.

Keeping both numbers is deliberate. A port that reaches 100 against a pin it
never advances has not reached parity with anything a user runs. Re-pinning is
the only way to close the second column, and `AGENTS.md` requires regenerating
every committed corpus in the same change, so the cost is real and the decision
belongs in the open rather than inside a single score.

## Method

Scores measure **reproduced surface**, not behavioral conformance. They come from
diffing inventories, not from running both implementations side by side:

- app-server JSON-RPC method names (91 upstream `SERVER_METHODS` plus 7 `clientTool/*`, counted from the pinned checkout by `scripts/parity/app_server_surface.py`);
- user-facing configuration keys (`vibe/core/config/vibe_schema.py` against
  `LayeredConfig::schema()`);
- published agent tool names and schemas;
- slash commands and CLI flags;
- module presence and depth, measured in lines of production code.

A part scores 100 when its externally observable contract is fully reproduced.
Anything measured only by module presence carries more uncertainty than anything
measured by name-level diff, and the table notes which is which.

Module presence is the weakest evidence there is, and the 2026-08-19 audit
showed why: every subsystem in this port was checked for whether anything
outside its own module and outside test code constructs it, and hooks was the
one that nothing does. A row that says a mechanism is reproduced now means it
runs, not that it compiles. Rows carrying **Measured by a differential oracle**
are replayed against a committed corpus; the others are inventory diffs or
structural judgements, and say so in place.

Every row of the parity table names the reference tree it was measured against,
so a reader can open the same files the score came from. Those paths are
relative to the checkout root recorded in the header, they are the state of the
reference at the pin, and the two the drift section names as moved say so in
place. Citing them rather than quoting them is what `NOTICE` requires.

Where a differential oracle exists, the score comes from running it rather than
from reading source, and the row says so and carries the command that
reproduces it. Twenty-eight modules matching `*_parity_tests.rs` hold those
replays, against corpora captured by the twenty-three capture scripts under
`scripts/parity/`, which sit beside three shared helpers, `harness.py`,
`pin.py` and `scenarios.py`, that capture nothing themselves. Four of the
capture scripts read the tool surface from a different angle:
`tool_surface.py` for the published names and schemas, `tool_config.py` for
the per-tool configuration keys, `tool_execution.py` for what a call returns
and `tool_presentation.py` for how a call and its result are shown, the last
of which drives the reference's own `ToolUIDataAdapter`. Every one of them
replays unconditionally; only the probe that recaptures from the pinned
checkout skips, so a missing or off-pin reference never fails `cargo test`.
Both counts were recounted 2026-08-23, by listing the files rather than by
adding one to the pair before them: `ls scripts/parity/*.py` answers 26, of
which the three helpers are not captures, and `find crates -name
'*_parity_tests.rs'` answers 28. The previous pair, twenty-seven and
twenty-two, was written before the managed shell pass added `shell_session.py`
and `session_parity_tests.rs`; the pair before that, twenty-six and twenty-one,
predates the worktree pass, which added one of each; and twenty-four and
nineteen predates the built-in tools and tool-infrastructure passes, which
added one of each apiece. A corpus is committed on the terms `NOTICE` sets:
names, pointers, verdicts and counts, with every reference-authored sentence
reduced to a length and a SHA-256. Each replay also carries a ledger of what is
still divergent, and fails both on a divergence no entry names and on an entry
whose divergence has stopped reproducing, which is what keeps a score from
drifting away from the code under it.

## Version drift: v2.24.0 to v2.24.2

Measured 2026-08-19 against reference `5e6aa0f`. This section is not a task
list; it is the size of the gap between the pinned target and the live one, so
the second score above can be read rather than trusted.

The app-server surface is the worst of it. Upstream now declares 96 methods
where the pin declared 91. **82 of the 96 are declared here, 14 are not, and 9
methods this port declares no longer exist upstream.** Seven of those 9 were
renamed rather than dropped, and the new name is one of the 14 missing:
`config/patch` became `config/write`, `callback/respond` became
`callback/result`, `history/list` became `session/history/list`,
`session/close` became `session/stop`, `session/compact/start` became
`session/compact`, `session/title/update` became `session/rename`, and
`shell/run` became `session/shellCommand`. The remaining two, `shell/interrupt`
and `config/thinking/write`, have no successor of their own. The seven other
missing methods are new: `events/read`, `plugin/info`, `plugin/reload`,
`session/history/get`, `session/turns/list`,
`workspace/trust/untrustedConfig` and `workspace/worktrees/remove`. An editor
written against today's `vibe/app_server/protocol.py` would fail on most of a
session's lifecycle here, and the failure would be a method-not-found on a name
this port never learned rather than a behavioral difference.

Behind that rename sits a rebuilt backend: `vibe/app_server/_session_backend_port.py`,
`vibe/app_server/_session_backend_services.py`, `vibe/app_server/_legacy_session_backend.py`
and `vibe/app_server/_legacy_session_runtime.py` are all new, and
`vibe/core/session/session_interop.py` with them.

Four other changes are user-visible on their own. `vibe/core/agents/models.py`
renamed the default agent profile from `default` to `ask` and moved its default
stance to accept-edits, so `--agent ask` and a `default_agent = "ask"`
configuration both fail here. `vibe/core/worktree.py` was replaced by
`vibe/core/git/worktree/` and `vibe/core/git/repo.py`, which is where the
worktree row's reference now lives. `vibe/core/config/vibe_schema.py` gained
`log_level` and `allowed_models`, neither declared here, with
`vibe/cli/textual_ui/widgets/log_level_picker.py` and a `/log-level` command
behind the first. `vibe/setup/auth/whoami.py` is new and is the console client
the `account/read` divergence below records as absent.

Row 2's own reference has moved, which is why the row scores 100 against the
pin and not against the product. At `5e6aa0f`, `vibe/cli/commands.py` declares
29 command keys and 36 aliases where the pin declares 28 and 35. The extra key
is the `/log-level` command named above, `build_retry_prompt` moved out of the
module entirely, `clear`'s description was rewritten, and the help document's
agent-cycling line now names `ask` where the pin names `default`. The completer
moved with it: `vibe/cli/autocompletion/completers.py` is +114 / -3 and
`vibe/cli/autocompletion/slash_command.py` +19 / -11 across the two releases,
and `vibe/cli/textual_ui/app.py`, which is where the echo and the help document
are mounted, is +924 / -210, the largest single-file change in the whole
`vibe/` diff. So this work closes row 2's first column and not its second: the
corpus is captured at `b78b451` and a re-pin regenerates it, and until then an
operator comparing the two products still finds one command upstream that this
port never learned.

The tool surface is the reassuring half: no tool was added or removed between
the two releases, and the only signature change is `file_path` moving from `str`
to a validated `ToolPath` alias in `vibe/core/tools/utils.py`, which publishes
the same JSON Schema. The notification vocabulary is unchanged.

One change is context rather than parity, and it is the most consequential thing
in the diff. v2.24.1 added `--experimental-harness` (`vibe/_experimental_harness.py`,
`vibe/app_server/_unified_harness_backend_adapter.py`), which swaps the Python
app-server's session backend for a `mistralai_rust_harness` distribution.
Upstream is moving its own core to Rust. Nothing in this document depends on
that; the strategy of this repository might.
